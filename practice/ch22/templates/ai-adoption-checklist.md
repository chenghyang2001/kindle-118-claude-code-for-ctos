# AI 導入四階段檢查表（附錄 A 整理）

> 來源：K118 附錄 A「四階段 AI 導入檢查表」的階段架構（Phase 1 Pre-Pilot、Phase 2 Pilot＋每週追蹤、Phase 3 Go/No-Go、Month 3–5 General Rollout）。
> 教材筆記只有階段名稱，下面的細項與數字是依全書各章內容整理；**書上沒有的數字一律標「假設值」**，導入前請換成自己團隊的基準。

## Phase 1：Pre-Pilot（預備，約 2 週，假設值）

- [ ] 指定一位負責人（Champion）與一位資安窗口
- [ ] 挑 1 個試點團隊、1～2 個低風險 repo（第 6 章沙盒候選評分）
- [ ] 記錄導入前基準：PR 週期、cycle time、缺陷率、onboarding 天數
- [ ] 各 repo 建 `CLAUDE.md`（技術棧、指令、慣例、禁止事項）
- [ ] 專案層 `.claude/settings.json`：deny 讀 `.env`、金鑰、正式環境設定（第 9 章）
- [ ] 決定採購路徑與金鑰管理（第 19 章：訂閱／API／雲端代理）
- [ ] 定義資料規則：哪些程式碼、資料不能進 AI
- [ ] 寫好 Go/No-Go 指標與門檻（見 Phase 3），先公告

## Phase 2：Pilot（實施＋每週追蹤，約 4–6 週，假設值）

- [ ] 第 1 週：Harness 設定、團隊共用提示詞庫（第 10、11 章）
- [ ] 每週追蹤：使用率、AI 參與的 PR 數、PR 退回率、遇到的阻礙
- [ ] 每週 30 分鐘回顧會：好用案例／失敗案例各一個
- [ ] 所有 AI 產出走正常 code review，不開例外
- [ ] 記錄成本（每人每週花費，假設值上限 $50）
- [ ] 收集開發者滿意度（1–5 分）
- [ ] 把踩過的坑寫回 `CLAUDE.md` 與反模式清單

## Phase 3：Go/No-Go 決策門檻

| 指標 | Go 門檻（假設值） | No-Go 訊號 |
| --- | --- | --- |
| 每週活躍使用率 | ≥ 70% 試點成員 | < 40% |
| PR cycle time | 比基準縮短 ≥ 20% | 沒變或變長 |
| 缺陷／回滾率 | 不高於基準 | 明顯上升 |
| 開發者滿意度 | ≥ 3.5 / 5 | < 3 |
| 資安事件 | 0 件 | ≥ 1 件涉及金鑰或客戶資料 |
| 成本 | 在預算內 | 超出預算 50% 以上 |

- [ ] 決策會議產出書面結論：Go／延長試點／No-Go，附原因

## Month 3–5：General Rollout（全員擴大）

- [ ] 分批擴大（每月加 1～2 個團隊，假設值），不一次全開
- [ ] 每個新團隊配一位試點成員當 buddy
- [ ] 組織層級的 CLAUDE.md 範本（前端／後端／資料管道／monorepo）
- [ ] 每週工作區支出儀表板、日誌匯出 SIEM（第 19 章）
- [ ] CI 加 AI 審查（第 20 章），但不當成唯一門檻
- [ ] 內部工具逐步做成 MCP server（第 22 章，見 `mcp-readiness-checklist.md`）
- [ ] 每季重算 ROI（第 4 章財務模型）
