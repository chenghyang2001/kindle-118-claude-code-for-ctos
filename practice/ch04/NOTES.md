# 第 4 章演練筆記：商業論證

> 快速 demo 模式：沒有經過 QA／審查流程，只跑過冒煙測試和交叉比對。

## 做了什麼

| 檔案 | 用途 |
| --- | --- |
| `pyproject.toml`、`uv.lock` | `uv init --bare` 建專案，`uv add openpyxl` 把套件裝在專案 `.venv` |
| `build_case.py` | 產生試算表、重算公式、讀回結果、交叉比對、寫摘要 |
| `business-case.xlsx` | 兩張工作表：`假設`（黃底可改，每列標「書」或「假設值」）、`計算`（三種情境，全部是 Excel 公式） |
| `BUSINESS-CASE.md` | 給老闆看的一頁摘要，數字全由程式從試算表讀出 |

執行方式：`PYTHONUTF8=1 uv run python build_case.py`（需安裝 LibreOffice）。

### 計算模型

- 每月效益 = 人數 × 年度全額成本 ÷ 12 × 效率提升 × 任務加權係數
- 任務加權係數 = 高影響佔比 × 權重 + 中影響佔比 × 權重（低影響任務不計效益）
- 一次性成本 = 培訓時數 × 時薪 × 人數 ＋ 週薪 × 2 週 × 生產力下降比例 × 人數
- ROI = （分析期效益 − 分析期總成本）÷ 分析期總成本
- 回本月數 = 一次性成本 ÷ 每月淨效益（淨效益 ≤ 0 時顯示「不回本」）

## 驗證結果

- `build_case.py` 冒煙測試通過：xlsx 和 md 都成功產生。
- 交叉比對通過：試算表公式算出的 ROI 與回本月數，和 Python 獨立計算的值完全一致（誤差 < 1e-9）。
- 用 openpyxl 重新讀取，確認 LibreOffice 重存後 `計算` 工作表仍然是公式，不是死數字。
- 基準情境結果：ROI 約 1343%、0.43 個月回本；保守 872%／0.71 個月；樂觀 2343%／0.22 個月。

## 和書上做法的差異

1. **數字來源**：書上給的只有 20% 基準效率（保守 15%、樂觀 30%）、2–4 小時培訓、前兩週生產力下降 10–15%。
   人數、薪資、工時、任務比例與權重、訂閱費、分析期間都是「假設值」，已在試算表與摘要標註。
2. **範圍值的取法**：書上給範圍，本練習把保守情境配最差端（培訓 4 小時、下降 15%），樂觀配最好端（2 小時、10%），基準取中間。
3. **公式重算**：openpyxl 只寫公式、不會算值，所以用 LibreOffice 無頭模式重存一次，才能讀到計算結果；
   使用獨立的暫存設定檔，避免和已開啟的 LibreOffice 衝突。書上若是讓 Claude 直接算數字，這裡改成「公式 → 重算 → 讀回」。
4. **生產力下降**當作一次性成本計入，沒有另外扣減前兩週的效益。

## 已知沒處理的風險

- 若改假設讓每月淨效益 ≤ 0，試算表會顯示「不回本」，但腳本的交叉比對和摘要格式化目前假設是數字，會報錯結束。
- 沒有 LibreOffice 的機器無法重算（腳本會明確報錯）；替代方案是改用 `formulas` 套件在 Python 內重算。
- 回本月數非常短（不到 1 個月），是因為假設的薪資高、訂閱便宜；實際導入請用公司數字重算。
