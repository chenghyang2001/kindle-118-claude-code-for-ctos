# 由單一函式產生單元測試

## 適用情境

- 已有實作、還沒有測試的純函式或小型模組。
- 想快速補上 happy path、邊界、錯誤三類案例。
- **不要用**：要求「先寫測試再實作」的 TDD 情境（改用規格→測試流程）；依賴外部服務、需要大量 mock 的函式。

## 變數

| 變數 | 說明 | 例 |
| --- | --- | --- |
| `{{FILE}}` | 函式所在檔案 | `src/pricing.py` |
| `{{FUNCTION}}` | 函式名 | `apply_discount` |
| `{{FRAMEWORK}}` | 測試框架 | pytest |
| `{{TEST_FILE}}` | 輸出測試檔路徑 | `tests/test_pricing.py` |

## 提示詞

```prompt
讀 {{FILE}} 裡的 {{FUNCTION}}，用 {{FRAMEWORK}} 寫單元測試，輸出到 {{TEST_FILE}}。

要求：
1. 只根據程式碼與 docstring 推論行為；不確定的行為寫成測試並加註「待確認」，不要改實作。
2. 至少涵蓋：正常案例、邊界值（0、空值、上下限）、錯誤輸入（應拋出的例外）。
3. 相似案例用參數化，每個案例名稱說明測什麼。
4. 不要 mock 被測函式本身；不要連網或讀寫真實檔案。
5. 最後列出：案例清單（一行一個）、你推論但無法確定的行為。
```
