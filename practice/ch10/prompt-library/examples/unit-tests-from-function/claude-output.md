## 推論但無法確定的行為

1. **捨入方式和 docstring 不一致**：docstring 寫「四捨五入」，但程式用的 `round()` 遇到剛好 .5 時是捨入到偶數（銀行家捨入），所以 2.5 會變 2，不是 3。這是 bug 還是預期，要問規格。
2. **rate 傳錯型別時拋的例外不同**：docstring 只寫範圍外拋 ValueError，但 `None` 或字串在比較時會拋 TypeError。不知道這樣是否可以接受。
3. **rate 可以傳 bool**：price_cents 明確擋掉 bool，rate 卻沒有，`True` 會被當成 1，商品變免費。兩邊處理不一致，看起來像遺漏。
4. **rate 傳 int 0 或 1 是否算合法**：docstring 寫「介於 0 到 1」沒指定型別，目前 int 也接受，我列為正常的邊界案例。
5. **price_cents 沒有上限**：超大整數乘以 float 會拋 OverflowError，不是 ValueError。
6. **浮點誤差下的捨入**：像 1000 × (1 − 0.7) = 300.00000000000006 這種剛好落在 .5 附近、又帶浮點誤差的情況，結果可能和人工計算不同。我只測了不受影響的例子，沒有找出會出錯的具體輸入。
