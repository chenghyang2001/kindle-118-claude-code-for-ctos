## 3. 缺口清單與修正建議

### G1 🔴 高額退款全自動，違反 HITL 矩陣（H1、H3）

- **問題**：退款到信用卡屬不可逆（R3），v1 讓代理自動退到 NT$10,000。依矩陣 > NT$5,000 應「禁止代理執行」。
- **風險**：模型錯判或被注入後，一次就造成無法追回的損失。
- **修正**：
  - 依矩陣分三段：≤1,000 自動＋事後通知；1,001–5,000 代理提案、主管事前確認；>5,000 只轉人工。
  - 新增「退款到購物金」選項（R2，可撤銷），代理優先提供此選項，金額門檻可放寬一級。

### G2 🔴 金額上限只寫在提示詞，可被提示詞注入繞過（B2、B4）

- **問題**：「上限 NT$10,000 寫在系統提示詞中」——提示詞不是安全邊界。
- **修正**：上限改在「退款服務閘道」（後端）強制，代理的服務帳號超過門檻的 `refund` 呼叫一律回 403；同使用者當日累計也由後端計算（防拆單）。紅隊測試列入上線條件。

### G3 🔴 沒有來源追溯與稽核日誌（P1～P3）

- **問題**：出事後無法回答「為什麼退了這筆？依據哪版政策？哪個模型版本？」
- **修正**：每筆決策寫入 append-only 稽核日誌，欄位見 v2 §7；代理無刪改權限。

### G4 🔴 沒有 AI 揭露、拒絕不附理由（T1～T3）

- **問題**：消費者不知道對方是 AI；被拒時不知道為什麼，也不知道怎麼申訴，客訴率指標反而會上升。
- **修正**：開場揭露；每個決策附「依據哪條政策＋哪項事實」的理由；拒絕時一定附「轉真人」按鈕。

### G5 🔴 沒有轉真人與 kill switch（H2、H4）

- **修正**：任何時候輸入「真人」或點按鈕即轉接，附對話摘要與代理判斷；客服主管與值班工程師可一鍵停用代理寫入動作（30 秒內生效，假設值）。

### G6 🔴 只有快樂路徑，沒有失敗模式（F1～F3）

- **問題**：付款 API 逾時重送 → 可能重複退款。
- **修正**：`refund` 帶冪等鍵（`order_id` + 申請 ID）；任何工具錯誤、模型逾時、低信心 → fail-closed 轉人工；v2 §8 列失敗模式表。

### G7 🟡 工具權限過寬（B5、B1）

- **問題**：`get_orders(user_id)` 允許查任意使用者；`issue_coupon` 沒上限。
- **修正**：查詢工具綁定「當前登入使用者」（user_id 由 session 帶入，不由模型填）；優惠券單次 ≤ NT$200、每人每月 1 張（假設值）。
