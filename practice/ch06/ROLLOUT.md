# ROLLOUT.md — Claude Code 四週漸進式導入路徑

> 來源：K118《Claude Code for CTOs》第 6 章「團隊導入」的 Four-week ramp path（Observe → Assist → Lead → Teach）。
> 標「（假設值）」的數字書上沒有，是本練習自訂的門檻，團隊可自行調整。

## 前置條件（第 0 週）

- [ ] 遴選 3–5 位試點開發者，刻意混搭：資深／資淺、積極者／**健康懷疑者**（書上建議）
- [ ] 選定 2–3 個具真實業務價值的沙盒專案（見 `SANDBOX-PROJECTS.md`）
- [ ] 沙盒專案已有初版 `CLAUDE.md`（團隊規範）與專案層 `.claude/settings.json`（deny 規則：`rm -rf`、`curl | bash`、`.env*`）
- [ ] 開好團隊頻道 `#claude-code`（或 `#ai-dev`）
- [ ] `FAQ.md`、`ANTI-PATTERNS.md` 初版已放進 repo
- [ ] 主管已知會：前兩週生產力可能下降 10–15%（書上第 4 章數字），不納入績效

## Week 1 — Observe（觀察）

**目標**：建立正確心智模型，先看別人怎麼用，不急著自己產出。

**活動**

- 旁觀一場資深成員的配對 Session（觀察 → 計畫 → 執行 → 驗證四步迴圈）
- 從頭讀一遍專案 `CLAUDE.md`，把看不懂的地方記下來
- 自己跑一次「安全提示詞」：唯讀分析任務，例如以 `--permission-mode plan` 請 Claude 解釋某模組，不改任何檔案
- 在 `#claude-code` 自我介紹並貼出第一個疑問

**完成標準**

- [ ] 至少觀察 1 場配對 Session
- [ ] 讀完 `CLAUDE.md`，提出 ≥ 1 個疑問或改進點（假設值）
- [ ] 完成 1 次唯讀安全提示詞，貼出結果截圖
- [ ] 能用一句話說出「什麼任務不該交給 Agent」

## Week 2 — Assist（輔助）

**目標**：在人類主導下讓 Claude 動手，練習「審 Diff」這個新核心技能。

**活動**

- 驅動 1–2 個小規模重構（單一模組、有測試覆蓋）
- 先用計畫模式讓 Claude 列出要改哪些檔案與原因，同意後才動手
- 逐行審查 Diff，不信任「測試通過」三個字，自己跑一遍
- 把疑問、卡關與失敗提示詞記在個人筆記，週末整理到 FAQ 候選

**完成標準**

- [ ] 完成 ≥ 1 個小重構並合併，PR 中附上使用的提示詞
- [ ] 每個 PR 都有人工逐行審查紀錄（非只看 CI 綠燈）
- [ ] 記錄 ≥ 3 條疑問／失敗經驗（假設值），提交到 FAQ 候選
- [ ] 沒有任何一次越過 deny 規則或改動 `.env*`

## Week 3 — Lead（主導）

**目標**：從頭到尾交付一個完整功能，並開始回饋團隊規範。

**活動**

- 用 PRD 五區塊（問題與指標、使用者故事、驗收條件、流程與邊界、技術備註）描述一個功能，交給 Claude 實作
- 提交前先讓 Claude 依 `CLAUDE.md` 做 Agent 預審，再送同儕審查
- 處理同儕審查意見（自己判斷，不是把意見原封丟回給 Claude）
- 為 `CLAUDE.md` 撰寫或修訂一個章節（例如錯誤處理慣例、測試命名）

**完成標準**

- [ ] 交付 1 個完整功能並通過同儕審查合併
- [ ] PR 描述含 PRD 連結與驗收條件勾選
- [ ] 提交 1 個 `CLAUDE.md` 章節的 PR 並被合併
- [ ] 能說出本週一次 Claude 做錯、你如何發現的案例

## Week 4 — Teach（教學）

**目標**：把個人經驗轉成團隊資產，成為下一批的導師。

**活動**

- 輔導下一位新成員走完他的 Week 1（帶一場配對 Session）
- 分享 2 個可複用提示詞到共享 Prompt 庫
- 在每週 30 分鐘 Insight-sharing 會議分享：1 個成功提示詞、1 個失敗案例、1 個 CLAUDE.md 改進建議（第 10 章格式）
- 提出 1 條團隊規範建議（可以是反模式、權限規則或審查流程）

**完成標準**

- [ ] 帶過 1 位新成員的配對 Session
- [ ] 2 個提示詞進入共享 Prompt 庫
- [ ] 在 Insight-sharing 會議完成一次分享
- [ ] 1 條規範建議已開 PR 或 Issue
- [ ] 填寫四週回顧問卷（滿意度、卡點、願意推薦給同事嗎）

## 四週結束後：Go / No-Go 判斷（假設值門檻）

| 指標 | Go 門檻（假設值） | 來源 |
| --- | --- | --- |
| 試點成員完成四週比例 | ≥ 80% | 假設值 |
| 試點期 PR 回滾／hotfix 數 | 不高於導入前基準 | 假設值 |
| 願意推薦給同事的比例 | ≥ 70% | 假設值 |
| 效率提升（穩定後） | 以 20% 為基準（保守 15%、樂觀 30%） | 書上第 4 章 |

達標 → 進入第二批（每位試點成員帶 1–2 人）；未達標 → 回顧 ANTI-PATTERNS，調整 `CLAUDE.md` 後再跑一輪。
